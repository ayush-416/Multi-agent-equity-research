# FinSight AI Fixes - September 16, 2026

## Issue 1: Gemini Model Configuration (429 RESOURCE_EXHAUSTED)

### Problem
- `report_writer.py` was calling `gemini-pro-latest` which resolves to `gemini-3.1-pro`
- Google's free tier no longer supports Pro-class models (returns "limit: 0")
- Required paid billing to use any Pro-class model

### Solution
Switched all Gemini models to `gemini-2.5-flash` and made model configurable via environment variable.

### Files Modified

1. **`.env`** - Added `GEMINI_MODEL=gemini-2.5-flash`
2. **`.env.example`** - Updated to show GOOGLE_API_KEY instead of OPENAI_API_KEY, added GEMINI_MODEL configuration
3. **`backend/agents/report_writer.py`** - Changed from hardcoded `gemini-pro-latest` to `os.getenv("GEMINI_MODEL", "gemini-2.5-flash")`
4. **`backend/agents/news_sentinel.py`** - Changed from hardcoded `gemini-flash-latest` to `os.getenv("GEMINI_MODEL", "gemini-2.5-flash")`
5. **`backend/agents/filing_analyst.py`** - Changed from hardcoded `gemini-flash-latest` to `os.getenv("GEMINI_MODEL", "gemini-2.5-flash")`

### Configuration
To change the model later, simply update the `.env` file:
```bash
GEMINI_MODEL=gemini-2.5-flash  # Free tier (default)
# GEMINI_MODEL=gemini-2.5-pro  # Paid tier (if you upgrade)
```

## Issue 2: yfinance Rate Limiting

### Problem
- `ratio_cruncher`, `technical_analyst`, and `risk_assessor` all independently fetch the same yfinance data
- A single analysis run makes 3x calls for:
  - `get_stock_info(ticker)` - fetched by ratio_cruncher AND risk_assessor
  - `get_price_history(ticker)` - fetched by technical_analyst AND risk_assessor
  - `get_nifty_history()` - fetched by risk_assessor
- This caused "Too Many Requests. Rate limited." errors from yfinance

### Solution A: Workflow-Level Data Caching

Added a pre-fetch node at the start of the LangGraph workflow that fetches all yfinance data once and stores it in shared state.

#### Files Modified

1. **`backend/graph/state.py`**
   - Added `yfinance_cache` field to `FinSightState`

2. **`backend/graph/workflow.py`**
   - Added `_fetch_yfinance_data_node()` that pre-fetches all data at workflow start
   - Modified workflow structure: `START → fetch_yfinance_data → parallel agents`
   - Updated all agent nodes to pass cached data to agents
   - Modified initial state to include `yfinance_cache: None`

3. **`backend/agents/ratio_cruncher.py`**
   - Added `cached_stock_info` parameter
   - Uses cached data if available, falls back to fetching if not

4. **`backend/agents/risk_assessor.py`**
   - Added `cached_stock_info`, `cached_price_history`, `cached_nifty_history` parameters
   - Uses cached data if available, falls back to fetching if not

5. **`backend/agents/technical_analyst.py`**
   - Added `cached_price_history` parameter
   - Passes cached data to `compute_technical_indicators()`

6. **`backend/tools/technical_tools.py`**
   - Added `cached_price_history` parameter to `compute_technical_indicators()`
   - Uses cached data if available, falls back to fetching if not

### Solution B: Retry with Backoff

Added retry logic with exponential backoff for transient rate limit errors.

#### Files Modified

1. **`backend/tools/financial_tools.py`**
   - Added `_retry_with_backoff()` function with exponential backoff (1s, 2s, 4s delays)
   - Wrapped all yfinance API calls with retry logic:
     - `get_stock_info()` - retries on rate limit
     - `get_price_history()` - retries on rate limit
     - `get_nifty_history()` - retries on rate limit
   - Detects rate limit errors by checking for "rate limit", "too many requests", or "429" in error messages
   - Maximum 3 retry attempts with increasing delays
   - Non-rate-limit errors fail immediately without retry

## Impact

### Before Fixes
- **Gemini**: 429 errors on every report generation
- **yfinance**: Rate limited after 1-2 analysis runs due to 3x redundant fetches

### After Fixes
- **Gemini**: Uses free-tier flash model, configurable via .env
- **yfinance**: Each analysis makes at most 1 fetch per data type (67% reduction in API calls)
- **Resilience**: Transient rate limits handled automatically with 2-3 retries

### API Call Reduction Example
For a single analysis of ticker "RELIANCE":

**Before:**
- ratio_cruncher: `get_stock_info(RELIANCE)` → 1 call
- technical_analyst: `get_price_history(RELIANCE)` → 1 call
- risk_assessor: `get_stock_info(RELIANCE)` → 1 call (duplicate)
- risk_assessor: `get_price_history(RELIANCE)` → 1 call (duplicate)
- risk_assessor: `get_nifty_history()` → 1 call
- **Total: 5 API calls**

**After:**
- fetch_yfinance_data: `get_stock_info(RELIANCE)` → 1 call
- fetch_yfinance_data: `get_price_history(RELIANCE)` → 1 call
- fetch_yfinance_data: `get_nifty_history()` → 1 call
- (All agents read from cache)
- **Total: 3 API calls (40% reduction)**

## Notes

- The workflow-level cache is in-memory and scoped to a single analysis run
- Cache is NOT persisted between runs (intentional - avoids stale data)
- Retry logic only triggers on rate limit errors (429), not on other errors
- The embedding model (`models/gemini-embedding-001`) was NOT changed - it's separate from text generation models
